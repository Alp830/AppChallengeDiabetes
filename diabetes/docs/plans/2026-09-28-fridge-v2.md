# Fridge & Meals V2 Implementation Plan

> **REQUIRED SUB-SKILL:** Use the executing-plans skill (or subagent-driven-development) to implement this plan task-by-task.

**Goal:** Make the fridge and meals flow easier to learn and use: a first-meal guide for new users, automatic retries with visible progress for AI calls, a fridge grouped by food type, saved recipes, and leave warnings for unsaved or in-progress work.

**Architecture:** Three parallel worktrees branch from `ui-refresh` (safety tag `pre-fridge-v2`) and merge back into `ui-refresh` in the order Fridge → API → Onboarding. New code goes in feature folders (`lib/ai/`, `lib/onboarding/`, `lib/meals/saved/`). Each worktree keeps its `lib/main.dart` edits small and inside the regions it owns (see "Ownership" below).

**Tech Stack:** Flutter (Dart `^3.12.1`), Material 3 (`lib/design/` tokens), Firebase Auth + Cloud Firestore, Gemini over raw `http`, `flutter_test` + `package:http/testing.dart` `MockClient`.

**Spec:** `diabetes/OutlienFridgeV2.md`. **Context:** `subsets/AGENTS.md` and `subsets/contexts/{fridge,meal-agent,shell-auth-env,ui,testing}.md`.

## 0. Settled decisions

| Topic | Decision |
|---|---|
| Branching | Worktrees `fv2/fridge`, `fv2/api`, `fv2/onboarding` from `ui-refresh`; all merge back into `ui-refresh`. Undo point: tag `pre-fridge-v2`. |
| Onboarding option | **Example first** plus a light coach mark: the Home card opens Meals with an example prompt filled in and the `Recommend a meal` button highlighted. It works with an empty fridge and asks one tap of the user. |
| Who sees it | New users: accounts created through sign-up after this ships. Sign-up writes `firstMealGuide: 'pending'` on `users/{uid}`. Existing accounts have no field and never see the card. |
| When it's done | When the first recommendation appears, or when the user taps Skip (on Home or Meals). It is then stored as `firstMealGuide: 'done'`. |
| Retry count | 5 attempts total. Attempt 1 shows the normal loading state; attempts 2–5 show `Retrying N/5`. |
| Retry spacing | Fixed 2 s between attempts. No parallel attempts. |
| Retried calls | Fridge photo scan, meal recommendation (including "Suggest something else" and "Add a balancing tweak"), and Q&A **answers**. Suggested-question chips keep failing quietly. |
| Retryable errors | Timeouts, network errors (`SocketException`/`ClientException`), HTTP 408, 429, 500, 502, 503, 504, and an empty or unparseable model reply (no candidates, no text, invalid JSON). |
| Not retried | Missing API key, HTTP 400, 401, 403, 404, blocked/safety replies, cancellation. These fail on attempt 1. |
| Per-attempt timeout | Scan 90 s (it thinks at level high), recommendation 45 s, Q&A answer 30 s. |
| Saved recipe view | The full recipe card: image, reason, ingredients, steps, `Log this meal`, and `Tap a line to ask` Q&A (with retry states). No `Add a balancing tweak`. |
| Duplicate saves | Match on normalized dish name + sorted ingredients. The Firestore doc id is a hash of that, so saving the same recipe twice updates one doc. |
| Storage | `users/{uid}/savedRecipes/{fingerprint}` (new rule). Onboarding flag lives on the user doc next to `mealQaTipSeen`. |

### Task B1: One retry helper

**Files:**
- Create: `lib/ai/ai_retry.dart`
- Test: `test/ai_retry_test.dart`

```dart
import 'dart:async';
import 'dart:io' show SocketException; // guarded: use string match on web (see isRetryableAiError)

/// Typed failure for Gemini calls so the retry rule can tell a temporary
/// hiccup from a request that will never succeed.
class AiRequestException implements Exception {
  const AiRequestException(this.message, {this.statusCode, required this.retryable});
  final String message;
  final int? statusCode;
  final bool retryable;
  factory AiRequestException.fromStatus(int status, String body) => AiRequestException(
    'Gemini request failed: $status',
    statusCode: status,
    retryable: const {408, 429, 500, 502, 503, 504}.contains(status),
  );
  @override
  String toString() => message;
}

class AiCancelledException implements Exception { const AiCancelledException(); }

/// Lets the screen stop a retry loop when the user leaves or cancels.
class AiCancellation {
  bool _cancelled = false;
  bool get isCancelled => _cancelled;
  void cancel() => _cancelled = true;
}

class AiRetryPolicy {
  const AiRetryPolicy({this.maxAttempts = 5, this.delay = const Duration(seconds: 2), this.attemptTimeout});
  final int maxAttempts;
  final Duration delay;
  final Duration? attemptTimeout;
}

bool isRetryableAiError(Object error) {
  if (error is AiCancelledException) return false;
  if (error is AiRequestException) return error.retryable;
  if (error is TimeoutException) return true;
  if (error is FormatException) return true; // unparseable model output
  final text = error.toString();
  return text.contains('SocketException') || text.contains('ClientException') ||
      text.contains('Failed host lookup') || text.contains('Connection closed');
}

/// Runs [attempt] up to [policy.maxAttempts] times. Calls [onAttempt] before
/// each attempt (1-based) so the UI can show `Retrying 2/5`. Never runs two
/// attempts at once. Throws the last error, or [AiCancelledException].
Future<T> runWithAiRetry<T>(
  Future<T> Function() attempt, {
  AiRetryPolicy policy = const AiRetryPolicy(),
  AiCancellation? cancellation,
  void Function(int attempt, int maxAttempts)? onAttempt,
  Future<void> Function(Duration) sleep = Future.delayed,
}) async { /* loop: check cancel → onAttempt → attempt (with timeout) →
  on error: rethrow if !retryable or last attempt; sleep(policy.delay); check cancel */ }
```

Note: `dart:io` isn't available on web. Don't import it; classify by type name/string as shown. Map a non-`Exception` `TypeError` from bad JSON shapes to `FormatException` in the services (B2).

**Steps:**
1. Failing tests with a fake `sleep` that records durations: succeeds on attempt 3 → `onAttempt` called with 1,2,3 and sleeps `[2s, 2s]`; always 503 → 5 attempts then throws; 400 → 1 attempt; missing key (`retryable: false`) → 1 attempt; cancel during sleep → throws `AiCancelledException` and no further attempts; an attempt that exceeds `attemptTimeout` counts as retryable; attempts never overlap.
2. Run: FAIL. Implement. Run: PASS. Commit.
